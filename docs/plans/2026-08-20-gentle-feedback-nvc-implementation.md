# CrowdSift 부드러운 피드백 구현 계획

## 결정

- 비폭력대화(NVC)를 순화 원칙으로 사용한다.
- NVC를 고정 문장 템플릿이나 심리 추측 도구로 사용하지 않는다.
- 기본 흐름은 `관찰 → 시청 경험 → 강요하지 않는 부탁`이다.
- 원문에 없는 감정·필요·칭찬·해결책은 만들지 않는다.
- AI가 댓글 작성자인 것처럼 가장하지 않는다.
- UI에는 `시청자의 뜻을 바탕으로 시프티가 표현만 다듬었어요`라고 알린다.
- 원문, 분류 결과, 핵심 의견, 순화문, 사용자 수정은 계속 분리 저장한다.

## 목표

- 공격성을 낮추면서 댓글의 유용한 뜻을 보존한다.
- 명령형과 보고서 말투를 줄인다.
- 크리에이터가 사람에게 조심스러운 제안을 받은 듯 편하게 읽게 한다.
- 순화문이 영상 개선에 바로 참고될 만큼 구체적이게 한다.
- 유용한 의견이 없는 악성 댓글에서는 피드백을 만들지 않는다.

## 등급별 표현 정책

- 안전 댓글은 원문을 그대로 보여준다.
- 주의 댓글에 유용한 의견이 있으면 부드러운 1인칭 표현으로 순화한다.
- 위험 댓글에 유용한 의견이 있으면 사람 말투가 아닌 사실 요약으로 전달한다.
- 위험 댓글의 원문은 기존 보호·확인 절차를 유지한다.
- 유용한 의견이 없으면 `전달할 수 있는 구체적인 개선 의견을 찾지 못했어요`를 표시한다.
- 의미가 불확실하면 순화하지 않고 직접 검토 대상으로 보낸다.

## 순화문 작성 규칙

- 한 문장 또는 두 문장으로 작성한다.
- 평가보다 구체적인 관찰을 먼저 쓴다.
- 원문에 근거가 있을 때만 시청 경험을 쓴다.
- 부탁은 선택 가능한 바람으로 표현한다.
- `조금`, `살짝`, `혹시` 같은 완충어는 문장당 하나 이하로 쓴다.
- 불만의 실제 강도를 지나치게 밝거나 가볍게 바꾸지 않는다.
- `해주세요` 명령형만 반복하지 않는다.
- `더 좋을 것 같아요`를 모든 문장의 기본 결말로 쓰지 않는다.
- 이모티콘은 기본적으로 사용하지 않는다.
- 원문에 없는 `항상 잘 보고 있어요`, `기대할게요` 같은 호감을 추가하지 않는다.
- 원문에 없는 장비 교체, 편집 방식 같은 해결책을 추가하지 않는다.
- `전반적으로`, `사용자 경험`, `개선이 필요합니다` 같은 보고서 표현을 피한다.
- 최근 순화문과 같은 어미·완충어·문장 구조가 연속되지 않게 한다.

## 이번 주 — Thread 1: 의미 계약과 스키마

- `feedbackCore`를 관찰, 시청 영향, 요청의 구조화된 값으로 나눈다.
- 각 값은 원문 근거가 없으면 `null`을 허용한다.
- 순화 가능 여부와 의미 불확실 상태를 명시한다.
- 순화 결과에 사용한 의미 요소를 기록한다.
- 기존 저장 데이터와 읽기 경로의 호환 방식을 정한다.
- 원문과 새 구조화 결과가 섞이거나 덮어써지지 않게 한다.
- 위험 댓글과 주의 댓글의 출력 계약을 분리한다.

## 이번 주 — Thread 2: 프롬프트와 안전 검사

- 순화 프롬프트를 NVC 원칙 중심으로 v5로 갱신한다.
- 고정 말끝 목록과 이모티콘 비율 지시를 제거한다.
- 현재 원칙과 충돌하는 프롬프트 예시를 교체한다.
- 구조화된 의미 요소만 사용해 문장을 만들게 한다.
- 원문에 없는 내용을 추가했는지 검증하는 단계를 강화한다.
- 유해 표현 복사, 가짜 칭찬, 가짜 해결책을 각각 실패 사유로 기록한다.
- 검사 실패 시 기존처럼 순화문을 버리고 안전한 대체 문구를 사용한다.
- 모델명, 프롬프트 버전, 처리 시각, 검사 결과를 남긴다.

## 이번 주 — Thread 3: Inbox 표현과 사용자 피드백

- `긍정적 피드백`을 `부드럽게 정리한 시청자 의견`으로 변경한다.
- 카드에 순화문을 먼저 보여주고 AI 개입 문구를 작게 표시한다.
- `시프티가 표현만 다듬었어요` 설명을 제공한다.
- 기존 원문 보기와 위험 경고 흐름을 유지한다.
- `이 표현이 더 편해요` 피드백을 추가한다.
- `뜻이 달라졌어요` 피드백을 추가한다.
- `너무 꾸며졌어요` 피드백을 추가한다.
- 사용자 피드백은 원문·AI 결과와 별도 기록으로 저장한다.
- 키보드 탐색, 스크린리더 문구, 모바일 줄바꿈을 확인한다.

## 이번 주 — Thread 4: 평가 세트와 출시 기준

- 기존 한국어 댓글 평가 세트를 새 계약에 맞게 확장한다.
- 가짜 칭찬, 가짜 감정, 가짜 해결책 사례를 추가한다.
- 명령형 반복, 같은 어미 반복, 과도한 완충 사례를 추가한다.
- 비꼼, 은어, 순수 모욕, 위험 속 유용한 의견 사례를 포함한다.
- 의미 보존과 정서적 완화는 별도 점수로 평가한다.
- 유해 표현 유출과 없는 내용 생성은 출시 차단 항목으로 둔다.
- 대표 댓글의 기존 출력과 새 출력을 나란히 검토한다.
- 관련 단위·통합 테스트를 실행한다.
- 완료 보고 전 `npm run lint`와 `npm run build`를 실행한다.

## 이번 분기 — Thread 5: 개인화

- 표현 강도를 `담백하게 / 부드럽게 / 다정하게`로 제공한다.
- 세 설정 모두 의미와 불만 강도는 동일하게 보존한다.
- 이모티콘 설정은 별도 선택으로 두고 기본값은 끈다.
- 사용자가 승인·거절·수정한 순화문을 같은 워크스페이스에서만 참고한다.
- 개인화 데이터의 삭제와 초기화를 지원한다.
- 개인화가 협박·혐오·개인정보 보호 기준을 낮추지 못하게 한다.

## 이번 분기 — Thread 6: Signal Digest와 검증

- 반복되는 개선 의견을 주제별로 묶는다.
- 각 요약에 근거 댓글 수와 확인 가능한 출처를 연결한다.
- 소수의 큰 목소리를 전체 시청자 의견처럼 표현하지 않는다.
- 크리에이터 인터뷰와 전후 문장 선호 테스트를 진행한다.
- 덜 상처받음, 의미 유지, 사람다운 느낌, 행동 가능성을 측정한다.
- 실제 사용자 수정 패턴으로 프롬프트와 표현 정책을 조정한다.

## 완료 기준

- 원문에 없는 칭찬·감정·필요·해결책 생성이 없다.
- 유해 표현이 순화문에 그대로 노출되지 않는다.
- 순수 악성 댓글에서 유용한 피드백을 지어내지 않는다.
- 주의·위험·불확실 댓글이 각 정책대로 표시된다.
- 사용자 수정과 평가 이력이 원본 데이터와 분리된다.
- 전체 테스트, lint, production build가 통과한다.
