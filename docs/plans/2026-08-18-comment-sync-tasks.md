# CrowdSift 댓글 동기화 구현 계획

## 작업 구조

```text
Task 1 핵심 엔진
       ↓ 상태 API 계약 확정
Task 2 날짜·진행 UI ─┐
                     ├→ 통합 검토
Task 3 운영 검증·문서┘
```

- Task 1은 DB·수집·예약 문맥을 유지하며 전용 작업에서 끝까지 진행한다.
- Task 2와 Task 3은 Task 1의 상태 API 계약 확정 후 각각 전용 작업에서 진행한다.
- 현재 작업에서는 결과 통합, 충돌 검토, 전체 테스트만 수행한다.

## Task 1 — 댓글 동기화 핵심 엔진

### 목표

- 한 주기에 최상위 댓글과 답글을 합쳐 최대 100개 처리한다.
- 새 댓글을 먼저 수집하고 남은 자리로 선택 날짜 방향의 과거 댓글을 수집한다.

### 기능

- 최초 실행: 최신 댓글부터 최대 100개 수집
- 최신 책갈피와 과거 책갈피를 DB에 별도 저장
- 매시간 새 댓글 우선 수집
- 새 댓글 15개면 과거 댓글 85개 수집
- 새 댓글 100개 이상이면 과거 수집은 다음 주기로 연기
- 중복은 AI 분석 없이 중복 개수만 기록
- 신규·수정 댓글만 AI 분석 작업에 연결
- 책갈피를 보존하며 최대 3회 재시도
- `지금 동기화`는 다음 실행 시간을 현재로 변경
- 완료 후 다음 실행 시간을 정확히 60분 뒤로 저장

### 상태 API 계약

- 단계: `예약됨 → 수집 중 → 분석 중 → 완료 / 일부 성공 / 실패`
- 값: 신규·수정·중복·실패·분석 개수, 다음 실행 시간, 과거 수집 완료 여부

### 완료 조건

- DB 테스트, 서비스 테스트, 전체 테스트, lint, build 통과
- Task 2가 사용할 상태 API 계약 확정

## Task 2 — 날짜 선택과 진행 화면

### 목표

- 사용자가 날짜를 고르고 실제 동기화 상태를 쉽게 이해하게 한다.

### 기능

- 문구: `어느 날짜의 댓글부터 가져올까요?`
- 오늘 이후를 선택할 수 없는 캘린더
- 문구: `최신 댓글부터 선택하신 날짜까지 가져옵니다.`
- `댓글 가져오기 시작` 버튼
- 예약·수집·분석·완료·일부 성공·실패 표시
- 진행 중 버튼 비활성화와 로딩 표시
- 실제 API의 신규·수정·중복·실패·분석 개수 표시
- 다음 자동 동기화 시간과 과거 수집 진행 상태 표시
- 오류 원인과 `다시 시도` 버튼 표시

### 완료 조건

- 가짜 타이머나 가짜 개수 없이 Task 1 API만 사용
- component test, 접근성 확인, lint, build 통과

## Task 3 — 운영 자동화 검증과 문서

### 목표

- 운영 환경에서 초기 100개와 60분 자동 동기화가 실제로 동작함을 증명한다.

### 기능

- Supabase Cron 5분 wake-up과 DB 60분 조건 확인
- 초기 수집 전후 시각·개수 기록
- 테스트 댓글 작성 후 약 65분 뒤 신규 저장 확인
- 신규 댓글만 AI 분석됐는지 확인
- YouTube quota와 OpenAI 사용량 기록
- OAuth 만료, quota 초과, OpenAI 오류 재시도 확인
- 비밀값 없는 구조화 로그와 운영 체크리스트 작성
- 실제 실행·배포·장애 대응 방법 문서화

### 완료 조건

- 운영 DB 기록, UI 결과, quota 기록 일치
- 다른 사람이 그대로 재현할 수 있는 체크리스트 완성

## 확정 기준

- 100개는 최상위 댓글과 답글의 합계다.
- 매시간 새 댓글이 최우선이다.
- 남은 수량으로 선택 날짜 방향의 과거 댓글을 이어서 가져온다.
- Supabase Cron이 5분마다 worker를 깨우고 DB가 60분 실행을 결정한다.
- 실제 숨김·삭제·신고는 포함하지 않는다.
